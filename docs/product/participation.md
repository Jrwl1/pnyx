# Participation model

Last checked: 2026-05-14

Pnyx uses hybrid participation: evidence is the main path, discussion is bounded and attached to concrete accountability entities.

## Lane 1: submit evidence

Users can submit:

- missing promises;
- sources;
- corrections;
- party-context updates;
- freshness issues;
- source conflicts.

These submissions enter moderation or editorial review before affecting canonical truth.

## Lane 2: discuss a specific page

Discussion starts on:

- promise pages, for evidence debate and contextual questions;
- politician pages, for broader context and aggregation of promise-related discussion.

Discussion does not start as a global forum. Global discussion is too easy to detach from source-backed accountability.

## Lane 3: report problems

Users can report:

- misinformation;
- duplicate claims;
- stale data;
- source problems;
- harassment;
- spam;
- legal or privacy concerns;
- moderation concerns.

Reports should enter a triage queue with entity, reporter, reason, affected content, and moderation history context.

## Guardrails

- Comments and canonical facts must use separate schema, APIs, permissions, audit trails, and moderation states.
- Public UI must not imply comments are verified truth.
- Moderators can hide, lock, remove, restore, or escalate threads.
- Rate limits and abuse telemetry must exist before public beta exposure.
- Notifications should support replies, reviewed evidence submissions, and moderator actions, with user preferences.
